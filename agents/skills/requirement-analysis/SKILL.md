# Requirement analysis

Identify the business outcome and affected users; inspect existing behavior before describing the change. Record functional and non-functional needs, user stories, measurable acceptance criteria, constraints, edge cases, dependencies and risks. Mark unknowns and ask for decisions when they change the intended outcome. Link related task and contract IDs. Use the hub requirement, user story and implementation-plan templates; label proposals separately from implemented behavior.
